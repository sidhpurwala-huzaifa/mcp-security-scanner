# MCP Security Scanner 0.1.5

## Version numbering

Problems with PyPI versioning required us to skip the intervening version numbers. This release is numbered **0.1.5**, with package metadata and the scanner runtime version aligned to the same value.

## Highlights

- Shared Streamable HTTP session handling across scan, health, and RPC, including JSON/SSE responses, initialization negotiation, session headers, and response-ID correlation.
- Legacy HTTP+SSE compatibility using a persistent receive connection, validated endpoint discovery, and explicit transport selection.
- Accurate pass/fail/error/skipped reporting. Failed initialization, enumeration, and active probes no longer masquerade as security passes; independent checks continue after probe failures.
- Bounded HTTP error diagnostics and redaction of supplied credentials and negotiated session tokens, with short-ID handling that preserves response structure.
- Packaging checks for the bundled scan schema and a reorganized README focused on current usage.

## Compatibility notes

- Reports use schema version 2. Consumers should read each finding's `status` and handle `passed: null` for error/skipped outcomes.
- Scan exit codes are 0 for completion without failures/errors, 1 for evaluated security failures, and 2 for incomplete scans with errors.
- Legacy transport support remains experimental. Requests are not automatically replayed or reconnected; pagination remains conservatively incomplete.
- Response budgets use network timeouts and checks between chunks/events rather than strict wall-clock cancellation. Short secrets embedded in unrelated words are deliberately left unchanged.

## Changes

Includes #17, #19, #20, #21, #22, #23, and #24: HTTP headers, package validation, transport/session handling, outcome classification, diagnostic redaction, and documentation cleanup.
